# 1. 필수 챙겨야 할 것
- 백업과 롤백
    - 하단 영향도 검토할 때 자연스럽게 백업해야할 범위도 나올테지만
    - 안전빵으로 전체 다 저장해두는 게 좋다.
    - 비단 데이터 뿐만 아니라, 컨테이너라면 기존 컨테이너 이미지도 stop 만 시키고 remove는 자제할 것.

# 2. 영향도 검토
- 해당 작업이 진행될 때 영향 받는 범위: 순단이 있는지, 요청 유실이 있는지 등
- 해당 작업이 실패 했을 때 영향 받는 범위: 백업 제대로 하지 않았을 때 잃을 수 있는 데이터가 뭔지? 등

# 3. 해당 솔루션의 version (A -> B) 에 대해 발생할 수 있는 요소들 확인
- ai 적극 활용
- 또는 해당 솔루션 Release note 확인

# 4. 작업에서 실패할 수 있는 지점들 아카이브
- 특히 사내시스템의 경우 네트워크 문제로 작업이 연기될 수 있음
- 앞서 3번과 연관된 항목들도 대응책이 각각 있을 것임
    - ex. Jenkins 업데이트의 경우 Plugin만 미리 update하거나 deprecated된 설정값을 미리 수정해놓는 등

# 기타
- 모든 작업은 회고가 중요하다.
    - 못한 점
        - 재발방지 대책
        - (에러라면) 해당 에러인지 알 수 있었던 포인트들
    - 잘한 점
        - workflow로 기록
- 작업하면서 사용한 명령어들은 따로 아카이브해두는 게 좋다.
    - 작업 중에는 기술적으로 싶이 이해하고 수행하기 어려울 수 있기 때문
